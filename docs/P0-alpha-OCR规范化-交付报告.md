## 3. 判据纪律（本阶段最重要的产出）

这套修复的失败模式不是"漏改"，而是**把正常内容改成恰好存在的另一个词**。因此每条"能修"的规则都配了"绝不改"的锁定测试：

| 规则 | 允许 | 拒绝（附测试） |
|---|---|---|
| 数字/字母互认 | `C02`→`CO2`、`Na02`→`NaO2`、`CC14`→`CCl4` | `1735948`、`1000`、`pH7`、`H20` 原样保留 |
| 化学式下标 | `Na2O2`→`Na₂O₂`、`Ca(OH)2`→`Ca(OH)₂` | `utf8`、`version2`、`resize2` 原样保留（`Ut`/`Ver` 不是元素符号） |
| 离子电荷 | `Ca2+`→`Ca²⁺`、`SO42-`→`SO₄²⁻` | `A+B`、`x-y`、`1735948-` 原样保留 |
| 方程式记号 | `===`→`→`、`02t`→`O₂↑` | 普通正文的 `=` 不动 |
| 跨行粘连 | 上一行以反应记号结尾、下一行以元素/数字开头 | 普通段落换行不合并 |
| 词典校正 | 唯一匹配 + **差异涉及生僻偏旁**（`氵溶液`→`溶液`） | 多解时拒绝；`溶池`→`溶液`（形近误识）**拒绝**，交由疑点标注 |

最后一条是刻意划出的**能力边界**：判断"池"与"液"长得像需要字形相似度模型，
用一条字符串规则去猜就会开始改正常内容。这类疑点全部由 `【OCR不清】` 如实暴露。

## 4. 设计决策（含踩过的坑，供后续维护）

1. **词典统计必须按 n-gram，且要有边界证据**：中文没有词边界，逐字切分拼不出「碳酸钠」；
   而 n-gram 会切出「酸钠溶」这类跨词碎片。最终方案是"出现 ≥2 次 **或** 至少一次落在自然边界上"。
2. **编号数字要能回溯到化学式**：`deleting` 早期实现里 `core` 用 `[A-Za-z0-9]*` 会贪婪吞掉
   `Ca2+` 的电荷数。最终改成 **core 只吃字母与括号、尾部数字单独分组**，
   按"最后一个数字是电荷、前面是下标"分配（正合教材写法）。
3. **规范化顺序**：先理方程式记号，再修化学式 token，最后处理离子电荷。
   反过来会让 `O2t` 整体被当成 token 而放弃（实测）。
4. **修好也要留痕**：修复成功会消掉偏旁，于是"这行 OCR 出过问题"这个事实也会消失。
   因此疑点证据在**修复之前**采集（`Normalize` 里 `suspiciousSource`），保证标注率 100%。

## 5. 明确的能力边界（未做，且不打算靠猜做）

- `氵谷氵夜`（两个字**各自**被拆成偏旁）：与「溶液」的编辑距离远大于 1，无法可靠还原 → **原样保留 + 标注**。
- `溶池`→「溶液」这类形近误识 → 同上。
- `Na202` 里的 `0`（两侧都是数字）：形态上无法判断是不是被认错的 `O` → 放行，
  正确写法应由转写词典兜（转写里老师念对了）。
- 教材图例/结构式（OCR 完全没读出来的部分）：本阶段不涉及，属于 P2 的范围。
