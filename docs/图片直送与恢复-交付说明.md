# 图片直送 + 语音转写恢复（v1.2）

> 本文只记录**为什么这样做**与**实测数字**，实现细节看代码注释。

## 1. 背景：真实数据到底长什么样

样本：某台机器上 2026-09-01 ~ 2026-10-22 的 **86 节课**（57.4 小时录音，6.31 GB WAV）。

| 项 | 实测 |
|---|---|
| 会话 | 86（completed 83 / failed 3） |
| 截图 | **5810 张**，平均 67.6 张/节（中位 75，最多 125，最少 1） |
| 截图类型 | annotation 3789（65%）、new_slide 1738（30%）、video 283（5%） |
| 截图尺寸 | 3840×2160（全屏原图不缩放），平均 508 KB，合计 2.88 GB |
| 转写块 | **0 行**（STT 全程失败，且被 FillMissing 的 catch 吞掉） |
| 笔记 | 83 份：61 份兜底（46 次没配 Key、12 次超时、3 次连接被拒），22 份正常 |
| 兜底笔记内容 | **61/61 只有「课件截图 OCR」，0 份有转写** |

结论：图片直送要解决两件事——**重复率**（下面）与**成本**（每张最多 1024 token，见 §3）；
而「笔记没有讲课内容」的根因是 STT 静默失败，不是兜底逻辑丢东西。

## 2. 重复图片有多少：73% 是同一屏

对 5810 张真图逐张算 pHash（32×32 灰度 → DCT → 64 bit），按会话比较相邻帧：

| 指标 | 数值 |
|---|---|
| 相邻帧汉明距离中位数 | **2 / 64** |
| 相邻帧距离 ≤8 的比例 | **73.3%** |
| 字节级完全相同的图片 | 101 张（38 组） |
| 相邻两帧 OCR 文本互为前缀 | 23.6% |

按「变化点切分 + 只留每屏最后一帧」（**簇尾**，因为批注是逐步加上去的，首帧信息最少）：

| 策略 | 保留张数 | 占比 | 体积 | DeepSeek 口径 token（86 节合计） |
|---|---|---|---|---|
| 原样全留 | 5810 | 100% | 2884 MB | 5.95M（off-peak 0.89 美元） |
| 阈值 6 | 1766 | 30.4% | 996 MB | — |
| **阈值 8（默认）** | **1612** | **27.7%** | **908 MB** | **1.65M（0.25 美元）** |
| 阈值 8 + 每节上限 30 | 1463 | 25.2% | 816 MB | 1.50M（0.22 美元） |

单节课差异很大：最忙的一节 125 张里只留 27 张，最静的一节 84 张里只留 **4** 张
（96.4% 的相邻帧是同一屏继续写字）。所以上限只是护栏，去重才是主力。

## 3. 视觉 token 的计费口径（不同供应商差 10 倍）

| 口径 | 公式 | 3840×2160 一张 |
|---|---|---|
| DeepSeek（deepseek-flash 支持视觉） | 自动缩放到约 1300×1300 总像素，**每张硬上限 1024** | 1024 |
| Qwen-VL 系（vLLM / DashScope） | ceil(w/28) × ceil(h/28) | **10764** |
| OpenAI gpt-4o/4.1 | 85 + 170 × 512px 块数（先归一到 2048/768） | 1105 |
| Claude | w×h/750（长边先压到 1568） | 1844 |

DeepSeek 侧另有硬限制：单请求 ≤600 张、请求体 **48 MiB**、单图 ≤32 MiB、
**图数 ≥15 时单边像素上限降到 4096**。4K 原图 30 张就有约 15 MB、125 张约 63 MB（超限），
因此**必须客户端缩放**：长边 1600、JPEG 质量 80 → 单张 34–112 KB（实测四张：112/41/71/34 KB）。

## 4. 留存算法（ScreenshotSelector）

三条规则，纯函数、可单测：

1. **空白丢弃**：近空白页（白像素 >92% 或灰阶标准差 <6）；
2. **变化点切分 + 簇尾保留**：与上一帧 pHash 距离 ≤ 8 视为同一屏，只保留该屏**最后一帧**；
3. **上限**：超过 VisionMaxImagesPerNote（默认 30）时，优先保留首帧/末帧/所有 new_slide 簇尾，
   其余按时间均匀抽样——保证笔记不会只覆盖前半节课。

pHash 落库（screenshots.phash）缓存：第一次（老库升级）要解码一遍全部截图，
之后只解码最终要发送的那几十张。

## 5. 恢复：让 LLM 真正收到转写

### 5.1 修掉的静默失败

| 位置 | 旧行为 | 新行为 |
|---|---|---|
| TranscriptAssembler.FillMissing | catch 只 Debug.WriteLine | 上报进度（第 N 块转写失败 / 共 M/N 块失败） |
| NoteProcessor.TranscribeTracksAsync | 失败返回空轨，无原因 | 返回错误列表；转写为空时把原因写进**笔记摘要** |
| SenseVoiceSttService（模型缺失） | 只报一句进度就 return "" | 原因经上面的链路进入摘要 |
| 兜底笔记 | 只有 OCR 时看不出为什么 | 摘要追加「本次未取到转写：…」 |

### 5.2 离线恢复工具 devtools/RecoverNotes

    # 只重新转写（不花钱，先验证模型是否正常）
    RecoverNotes --db "%LOCALAPPDATA%\ClassNote\classnote.db" --stt-only

    # 重新转写 + 按当前设置重新生成笔记（先在小样本上验证）
    RecoverNotes --db ... --session 9ea701c5 --mode vision --max-images 30 --max-edge 1600

    # 覆盖 LLM 配置（会写入 settings.json）
    RecoverNotes --db ... --llm-base-url http://192.168.10.40:7080 --llm-model qwen2.5-vl --vision-model qwen2.5-vl

实测（本仓库样本，40 分钟 73 MB 的 WAV）：**80 块 / 6125 字 / 约 2.5 分钟**，
转写内容为真实课堂对话（「数学课不是觉课考试该……4号不号上课，6号7号考试……」）。

### 5.3 端到端验证（mock LLM 抓请求体）

用 _inbox/realdata/mock_llm.py 起一个 OpenAI 兼容 mock，跑恢复后抓到的请求体：

| 请求 | 内容 |
|---|---|
| req-001（第 1 段） | 235 KB；转写区块存在；2 张图（112 KB / 41 KB）；caption 「[图片 1] new_slide @ 00:09」「[图片 2] annotation @ 03:19」；**无 OCR 区块** |
| req-002（第 2 段） | 154 KB；2 张图（71 KB / 34 KB）；caption 「[图片 1] annotation @ 09:49」「[图片 2] new_slide @ 39:49」 |
| req-003（合并） | 11 KB；纯文本 |

即：**转写确实进了提示词，图片按 OpenAI 多模态格式（content 数组 + image_url data URL）分段落发送，每张只出现一次。**

## 6. 设置项（设置 → OCR 识别）

| 设置 | 默认 | 说明 |
|---|---|---|
| 笔记里的截图用什么形态 | **仅截图图片** | 仅图片 / 仅 OCR 文本 / 两者 |
| 每节课最多送 | 30 张 | 选图上限 |
| 长边 | 1600 px | 缩放上限（0 = 不缩放） |
| JPEG 质量 / 去重阈值 | 80 / 8 位 | 一般不暴露给界面，可在 settings.json 手改 |

> ⚠️ 选「仅截图图片」时必须配置**支持视觉**的模型（DeepSeek 是 deepseek-flash；
> deepseek-v4-pro 不支持视觉）。若模型不支持，调用会返回 4xx；
> 此时把这节课切回「仅 OCR 文本」重新生成即可。


## 8. 数据留存、收藏与「重新生成」（v1.3）

### 8.1 只留原料的"结果"，一周后清掉

| 阶段 | 行为 |
|---|---|
| 转写成功 | 立刻删除原始 WAV（每节 40 分钟约 73 MB）；保留 **转写块 + 截图** |
| 转写失败 | **保留音频**（唯一的补救素材），下次可 RecoverNotes --stt-only 重转 |
| 7 天后 | 非收藏会话的**截图（文件+行）、转写块、音频**删除；笔记正文与会话记录一直保留 |
| 护栏 | **一块转写都没有的课不清理**——音频是唯一能补救的素材（正是现场 86 节课的状态）；等它转写成功后才开始计时 |
| 时长可调 | 设置 → 录音设置 → 「原料留存（天）」，0 = 不清理 |

清理入口：ContentRetention.RunOnce（启动后台跑一次，失败只留痕），
实际删除逻辑在 LocalRepository.PurgeExpiredContent。

### 8.2 收藏 = 永不清理

- 数据：sessions.is_favorite（幂等补列）
- 按钮：笔记页工具栏「收藏 / 已收藏」（空心星 → 实心星），主页列表标题前显示 ★
- 语义：收藏后这节的音频（若尚未删除）、转写、截图都不被过期清理回收。
  注意"转写成功后音频已删"与收藏无关——想留音频就把留存天数调大（如 0 = 永不清理）。

### 8.3「重新生成」按钮

- 位置：笔记页工具栏 →「重新生成」
- 行为：读库里已保存的 transcript_chunks + 截图，按当前设置（图片直送 / OCR / 两者）重跑 LLM；
  **不重新转写、不重新录音**；旧笔记被覆盖
- 无素材时：直接跳过 LLM 并在摘要里写明原因（不会白花一次调用）
- LLM 失败时：仍走兜底笔记，正文里带转写原文
- 实现：INoteProcessor.RegenerateAsync = ProcessAsync(sessionId, audio: null)，
  无音频时从 transcript_chunks 载入转写（见 NoteProcessor.TranscribeTracksAsync）

### 8.4 测试

新增 12 个用例（留存清理、收藏白名单、双音轨删除回归、重新生成读转写/覆盖旧笔记/无素材跳过/
LLM 失败兜底、转写成功后删音频、转写失败保留音频），全部通过；全量用例通过数见文末。

## 9. 仍然存在的缺口

1. **没有界面入口**：恢复目前只能跑 RecoverNotes；主页/笔记页还没有「重新生成」按钮。
2. **音频目录里的 system 轨不会随会话删除**（DeleteSession 只删 audio_path）。
3. %TEMP%\classnote_*.wav 从不清理。
