# ClassNote v0.7 笔记提速 · 实测报告（NoteBench）

**被测**：ClassNote-Standalone（WPF / .NET 8，Release 构建，本地改动未提交版本）
**日期**：2026-09-12
**工具**：`devtools/NoteBench`（本次新增）
**方法**：真机 + 真实 SenseVoice-ONNX INT8 模型，同一台机器、同一素材；全部数字来自
`Stopwatch`、`Process.TotalProcessorTime` 与 SQLite 落库结果，无估算。

---

## 1. 环境规格

| 项 | 值 |
|---|---|
| CPU | Intel(R) Xeon(R) E-2124 @ 3.30GHz，**4 核 / 4 逻辑线程** |
| OS | Windows 10 专业版 22H2（19045） |
| .NET | SDK 8.0.423 |
| 模型 | SenseVoice-Small ONNX INT8 `model_quant.onnx` = 241,216,270 B |
| 素材 | `%TEMP%\classnote_bench_95s.wav`：95.61 秒 / 16kHz 单声道 PCM16，由 `TestResults/bench/speech-test.wav`（SAPI 合成中文语音）重复拼接而成，**4 块**（跨 3 个块边界） |

> 素材为什么这样造：只有一段 15.94 秒的语音只有 1 块，测不到块边界、末块不足、预加重跨块传染这些
> 真正容易出错的地方。拼接出来的 95.61 秒跨 3 个边界，末块只有 559 帧。

## 2. 结果一：边录边转写与整文件转写**逐字相同**（核心正确性）

命令：`NoteBench identity <wav>`（slices=320,1600,640 模拟采集回调的不齐分片）

| 指标 | 结果 |
|---|---|
| 音频 / 块数 | 95.61 秒 / 4 块 |
| 整文件路径（公开入口 `TranscribeAsync`） | 20.29 秒，379 字 |
| 整文件路径（逐块内部入口） | 14.23 秒 |
| 边录边转写（生产 `PcmBlockBuffer` + 同一块推理入口） | 13.49 秒，产出 **4** 块 |
| **逐块差异** | **无 ✓** |
| **整体文本相同** | **是 ✓** |
| 总采样对齐 | 1529760 / 1529760 ✓ |

### 含"让路暂停"的对拍（模拟检测到全屏放映）

命令：`NoteBench identity <wav> --pause-at 0.45 --slices 320`

| 指标 | 结果 |
|---|---|
| 暂停 / 恢复 | 在第 1 块处暂停 → 恢复时跳到块 3 重新开始 |
| 产出块 | 块 0 与块 3（共 2 块），块 1、2 交由课后补算 |
| **逐块差异** | **无 ✓**（跨越暂停边界之后算出的块仍与整文件逐字一致） |
| 总采样对齐 | 1529760 / 1529760 ✓ |

**为什么这组数字足够**：两条路共用同一个块推理实现（`SenseVoiceSttService.TranscribeChunk`），
所以只要"喂进去的窗口、块前采样、帧数、块号顺序"相同，输出必然相同。
`TranscriptionChunkingTests` / `PcmBlockBufferTests` 从数学与缓冲两侧锁住这些输入，
本报告用**真实模型**在端到端层面复核。

## 3. 结果二：留一半核的代价可以忽略

命令：`NoteBench stt <wav> --threads 4|2`

| intra-op 线程 | 冷调用（含模型加载） | 温调用 | **RTF** |
|---|---|---|---|
| 4（占满 4 核，即旧行为） | 20.47 秒 | 12.96 秒 | **0.136** |
| **2（留一半给 PPT / 视频）** | — | 13.89 秒 | **0.145** |

- 模型加载 ≈ **6.74 秒**（冷 − 温推算；与既有 bench 报告的 6.05 秒同量级）。
- **只为课堂让路而少用一半核，转写只慢 6.7%**——本模型在 4 核上并行收益早已饱和，
  所以"最多占一半逻辑核"这条硬约束几乎是免费的。这是本次改动中最有价值的实测结论之一。

## 4. 结果三：课堂模拟（按真实时间喂帧，走生产代码）

命令：`NoteBench classroom <wav>`（自动档）
实现路径：**生产代码** `IncrementalTranscriptionSession` + `ClassroomResourceGovernor` +
`TranscriptTrackWorker` + `PcmBlockBuffer` + 真实 SQLite 落库 + `TranscriptAssembler` 装配。

| 指标 | 结果 |
|---|---|
| 音频时长 / 模拟课堂时长 | 95.6 秒 / 95.6 秒（20ms 一帧，按真实时间节流） |
| **课堂期间 CPU** | 累计 **20.5 核·秒** ⇒ 平均占整机 **5.4%** |
| 课堂进度 | 已转写 96 秒 / 落库 **4** 块 |
| **课后残余等待** | **3.6 秒**（收尾完成） |
| 装配结果 vs 整文件 | **相同 ✓**（379 字） |

外推到一节 90 分钟课（按 0.214 核·秒 / 音频秒，双路 ×2）：

| 场景 | 课堂期间平均占整机（4 核） | 课后残余等待 |
|---|---|---|
| 90 分钟 · 单路 | ≈ 5.3% | ≤ 一块（30 秒音频 ≈ ≤5 秒）+ LLM |
| 90 分钟 · 双路 | ≈ 10.7% | 同上（两路并行补算） |

对照**旧行为**（课后整段转写，同样的 RTF）：

| 场景 | 旧：课后转写等待 | 新：课后转写等待 |
|---|---|---|
| 90 分钟 · 单路 | 5400 × 0.145 ≈ **13.0 分钟** | ≤ 5 秒 |
| 90 分钟 · 双路 | ≈ **26.1 分钟** | ≤ 5 秒 |
| （按既有 bench 报告在负载机上测得的 RTF 0.29 计） | 26 / 52 分钟 | ≤ 5 秒 |

## 5. 结果四：工程侧

| 项 | 结果 |
|---|---|
| 主程序构建（Release） | 0 错误 |
| 单元测试 | **308 通过 / 0 失败**（改动前 256，本次新增 52 条） |
| 应用冒烟启动 | 主窗口正常出现（`ClassNote - 课堂笔记助手`），无崩溃 |
| 渲染回归（`devtools/RenderHarness`） | 15 张页面全部渲染通过，含录音页 3 种来源、设置页 2 个页签（新增的「课堂占用」下拉正常显示） |

新增测试清单（全部针对本次新增逻辑）：

- `TranscriptionChunkingTests`：块数/帧数/窗口与旧实现的 `for (start += 3000)` 循环逐长度对齐；
  **按块算 fbank 与整文件算完再切块逐元素精确相等**；并反向验证"漏掉块前一个采样会改变首帧"（证明该断言不是恒真）。
- `PcmBlockBufferTests`：块号连续、每块帧数、块前采样、窗口内容、分片大小无关性、
  **暂停/恢复后重对齐**、**丢帧后对齐且只作废受影响块**、边界落在缺口内的作废、超短音频不产出。
- `TranscriptAssemblerTests`：**增量装配结果与批量路径逐字相同**（同一假推理器，真 WAV 文件）、
  只补缺块、全部命中时不读音频、非法格式回退整文件、采集侧计数偏大不丢内容、拼接口径。
- `ClassroomResourceGovernorTests`：**intra-op 永远 ≤ 一半逻辑核**、占空比换算、
  放映/视频/电池/超预算各档、手动暂停、档位存储与回退。
- `TranscriptChunkStoreTests`：块落库往返/覆盖/音轨与会话隔离/空文本/删会话级联清理；
  截图 OCR 的 null（未识别）与 ""（识别过但无字）区分。
- `NoteSegmenterOcrDedupTests`：OCR 重复折叠的保守边界（只折相邻且归一化后完全相同）。
- `WavePcmTests`：data 块定位、**头部声明长度为 0 时以文件实际长度为准**、窗口与块前采样、
  末尾截断、格式判定。

## 6. 本次**未**测到的（如实申报）

| 未测项 | 原因 | 风险与后续 |
|---|---|---|
| 真机麦克风/回环录音链路（tap → 队列 → 工作线程） | 本环境无音频设备 | 采集回调里的订阅点已按"必须立即返回"实现（只做一次拷贝入队），但**必须在有声卡的机器上用 `devtools/AudioProbe` 做一次真机冒烟**（含"两路同时录"） |
| 全屏放映 / 视频播放的真实探测 | 无 PowerPoint 放映与视频播放场景 | `SystemResourceProbe` 的 Win32 路径（`GetForegroundWindow` + 显示器覆盖率、`GetSystemPowerStatus`）未在真机上断言，策略层已被单测覆盖 |
| 电池供电降速 | 台式机，无电池 | 同上，策略与折算公式已单测 |
| 双路并行的真实并行度 | 只有单路素材 | 两路并行是 `Task.WhenAll` + 同一 ORT 会话（Run 线程安全），建议真机上用两段音频实测总耗时 |
| LLM 分段并行的收益（P1-1） | **不属于本次范围** | 本次只做了 P1-2（HttpClient 复用）；分段并行仍需跨任务限流，另立项 |
| 端到端 UI 出笔记（含 LLM） | 本机未配置 API Key | LLM 阶段除连接复用外未改动 |
| 90 分钟长音频的整段实测 | 单次 STT 需 ~13 分钟，本次以 95.61 秒 × 外推代替 | 外推口径已在 §4 写明；建议发布前用一节真实课堂录音复测 |
| `NoteProcessor` 取用增量会话的那段胶水代码 | `NoteProcessor` 内部直接用 `LocalRepository.Instance`（真实用户库），照既有测试约定不能在单测里跑它 | 该胶水约 20 行（取会话 → 等尾部 → 逐路装配 → 用完注销），由代码评审覆盖；**增量会话 + 落库 + 装配**这条链路由 `classroom` 命令用临时库端到端跑通 |

## 7. 复现方式

```powershell
# 1) 造素材（把 TestResults/bench/speech-test.wav 的 data 块重复 6 次拼成 95.61 秒）
#    见本次会话脚本；或用任意 16kHz 单声道 PCM16 长音频

# 2) 分块计划（不需要模型）
dotnet run --project devtools/NoteBench -c Release -- chunks   $env:TEMP\classnote_bench_95s.wav

# 3) 留一半核的代价
dotnet run --project devtools/NoteBench -c Release -- stt      $env:TEMP\classnote_bench_95s.wav --threads 4
dotnet run --project devtools/NoteBench -c Release -- stt      $env:TEMP\classnote_bench_95s.wav --threads 2

# 4) 逐字对拍（含让路暂停）
dotnet run --project devtools/NoteBench -c Release -- identity $env:TEMP\classnote_bench_95s.wav
dotnet run --project devtools/NoteBench -c Release -- identity $env:TEMP\classnote_bench_95s.wav --pause-at 0.45

# 5) 课堂模拟（真实时间 1× 喂帧，测课堂占用与课后残余）
dotnet run --project devtools/NoteBench -c Release -- classroom $env:TEMP\classnote_bench_95s.wav
```

退出码 0 = 逐字相同；非 0 = 存在差异（并打印差异定位）。可直接接进 CI。
