## 3. 审计中发现的缺陷

### 🔴 缺陷 1（致命）：笔记页每一对括号都变成了公式

**现象**（用户截图）：笔记里写的是 `d[i][j]`，页面渲染成「d / i / j」三行居中大字。

**根因**：`ClassNote/ViewModels/NoteViewModel.cs` 里 MathJax 的分隔符配置写错——

```js
tex: { inlineMath: [['(', ')']], displayMath: [['[', ']']] }   // 错
```

本意是 LaTeX 的 `\(...\)` 与 `\[...\]`，但反斜杠丢了。于是**每一对圆括号与方括号都被当成公式**，
而方括号是"行间公式"、CSS 又给它 `display:block; text-align:center`，就被单独拎出来居中并撑开空隙。

**破坏程度（用真实笔记实测，`devtools/NoteRender`）**：

| 配置 | 公式节点数 | 首段文本 |
|---|---|---|
| 修复前 | **59 个**（全是假的） | `…定义问题：d ⏎ 𝑖 ⏎ 𝑗 ⏎ 等于 S1 的前 i 个字母…` |
| 修复后 | **0 个** | `…定义问题：d[i][j] 等于 S1 的前 i 个字母…` |

不止是排版难看——`f(n-1)+1` 被渲染成 `f𝑛 − 1 + 1`（**括号消失、变量变斜体数学体**），
数学语义都被改了；`min(a+1, b+1, c+1)` 同样丢了括号。

**修复**：
1. 分隔符改成 LaTeX 标准 `\(...\)` / `\[...\]`（**正是 Markdig 数学扩展吐出的形式**，两边必须一致）；
2. CSS 选择器从 `.math.inline` / `.math.display`（Markdig 从不生成这两个类名，等于样式从未生效）
   改成 `span.math` / `div.math`，并给 `mjx-container` 加横向滚动兜底；
3. Markdown 管线与 HTML 模板抽到 **`Services/NoteHtmlRenderer.cs`** 单一实现——
   公式渲染的三段（Markdig 输出 / MathJax 分隔符 / CSS 选择器）必须彼此对齐，分散在多处正是本次事故的土壤。

**回归防护**：`NoteHtmlRenderer` 的配置与选择器由 4 条单测锁死（含"三种错误写法一个都不许回来"）；
`devtools/NoteRender` 能真跑 WebView2 + 离线 MathJax 并断言"裸括号没被当成公式"——
`--legacy-config` 会**故意复现事故**，退出码 1，可当 CI 门禁。

> ⚠️ 关键事实：**这是渲染侧缺陷，不是数据侧**。升级后**已有笔记直接正常显示，无需重新生成笔记**。

### 🟠 缺陷 2：PDF 导出把 Markdown 标记原样印出来

`PdfExportService` 逐行打印 `ContentMarkdown` 原文，因此 PDF 里会出现字面的 `**加粗**`、`$公式$`、反引号；
且识别有序列表的正则写成了 `@"^d+[.)]s+"`（**`\d`→`d`、`\s`→`s`，转义在源码里丢了**），
永远匹配不上，编号列表形同虚设。

**修复**：新增 `Services/MarkdownInlineText.cs`（纯函数）：消化 `**加粗**`/`__加粗__`/反引号/链接/转义符，
公式只脱掉 `$` 分隔符而保留原文（QuestPDF 排不了 LaTeX，保留 `d[i][j]` 比印出美元符有用），
并把 `[i][j]` 这类数学下标写法**原样保留**（它是引用式链接语法，绝不能吃掉）；
有序列表识别支持 `1.` / `2)` / `1、`。文字内容一字不改，与全局"技术内容逐字保真"口径一致。

### 🟡 缺陷 3：录音时长与会话时间戳漂移（-4%）
会话表里 `duration=1262`，而音频实际长度是 **1314 秒**（少 52 秒 / 4%）。
原因：`ElapsedSeconds` 由 `DispatcherTimer` **每秒累加**，UI 线程被截图落库/进度刷新占住时 tick 会被推迟。
这个数字既写进会话时长、又当截图的时间戳，因此笔记里的 `[new_slide @ 20:50]` 之类标记也整体偏早。

**修复**：改用 `Stopwatch` 墙钟计时（`_elapsedTimer.Tick` 里读墙钟而不是自增）。

### 🟡 缺陷 4（审计发现 → 已实现并实测）：托盘常驻期间模型独占 600MB

**现象**：审计时用户的实例运行中，工作集 **929 MB**，其中约 600MB 是 STT 模型。
v0.7 把"每会话重载 + 跨会话泄漏（旧版累积到 1.8GB）"换成了"单例常驻"，
但托盘常驻的应用于是**整天**占着这 600MB —— 对 8GB 内存的机器是实打实的代价。

**实现**：`Services/ModelIdleReleaser.cs` + `SenseVoiceSttService` 闲置释放——
闲置 **10 分钟**后释放 `InferenceSession`，下次用到自动重载；开录预热是重载入口，因此用户无感。
三条不变量：**推理进行中绝不释放**（否则正在跑的 `Run` 会崩溃 → 整条音轨白录）、
活动会重置闲置窗口、释放失败不计入且下一轮重试。

**真机实测**（`NoteBench memory`，本机、真模型）：

| 阶段 | 工作集 | 私有内存 |
|---|---|---|
| 基线（未加载） | 23 MB | 7 MB |
| 加载后 | **551 MB** | **557 MB** |
| 生产定时器**自动**释放后（阈值 6 秒，实测 46 秒内触发） | **64 MB** | **37 MB** |
| 释放相对加载后 | **−488 MB** | **−521 MB** |

- 释放由**生产定时器**触发（不是手动调用 `TryRelease`），46 秒的等待与"每分钟一次检查"完全吻合；
- 释放后重新转写同一份 95.61 秒音频：**文本逐字一致**（379 字 vs 379 字），重载+转写共 20.4 秒（其中模型加载约 6.8 秒）；
- 结论：**600MB 常驻 → 闲置后只剩约 64MB，且重载对结果与用户均不可见**。

> 配置：`IdleReleaseAfter`（0/负数 = 关闭自动释放）。当前是代码级默认值，**尚未做成设置界面选项**。

### 🟠 缺陷 5（用户报告 → 已定位并修复）：主页「最近记录」会整片空白

**症状**（用户报告）：主页最近记录一条都不显示，而库里明明有记录。

**根因**：筛选条件 `CourseFilter` 双向绑定在筛选下拉的 `SelectedItem` 上，`CourseFilters` 是它的 `ItemsSource`。
旧实现刷新候选集是 `Clear()` + 全量重加，而 **WPF 的 `Selector` 在 ItemsSource 被清空时会把 `SelectedItem`
置为 null**，双向绑定把这个 null 写回 `CourseFilter` ⇒ 筛选条件变成"谁都不匹配"的 null ⇒
`ApplyFilter` 之后可见列表为空（页面只剩「当前科目下暂无记录，可在上方切换『全部课程』」）。

**证据**：`MainPageFilterBindingTests` 用**真 ComboBox + 真 WPF 绑定引擎**直接断言了这条机理
（`WpfComboBox_PushesNull_WhenItemsSourceIsCleared` 观察到的写入序列里确实有 null）。

**修复**：① `RebuildCourseFilters` 改为原地增删（ItemsSource 永不清空，从源头断链）；
② `CourseFilter` 遇 null/空白一律回退「全部课程」（兜底，控件因换模板/虚拟化重建推空也不怕）。

**为什么单测没能早发现**：ViewModel 单独看完全正确（默认值就是「全部课程」，且早有用例覆盖），
缺陷只存在于**控件与绑定的交互**里——所以这次的回归测试必须把真控件拉进来。

### 附带发现：笔记里一个 `$` 都没有

那份笔记全文 3,897 字**没有任何 LaTeX 标记**——模型把公式当普通文字写（`f(n) = min(f(n-1)+1, …)`）。
渲染器修好之后这类文本已经能正确显示，但要**真正排成数学公式**必须让模型用 `$...$`。
已在共享保真规则里追加第 6 条：公式用 `$...$` 包裹、**只补分隔符不改内容**，
并要求"不要把普通句子包进 `$...$`"；合并与最终润色环节也追加了"公式分隔符必须原样保留"。
> 该条属提示词行为，**本次无 API Key 未能实测**，需下一次真实生成时确认效果。
